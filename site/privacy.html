Borea

Privacy

Borea has no account, no analytics and no server of its own. This page lists every server it contacts and the switch for each one that has a switch.

In short

  • Borea collects no usage data, no telemetry and no crash reports, and it sends nothing about you anywhere, except what you choose to share or publish.
  • Your instances, mods, settings, logs and backups stay in folders on your computer. Nothing is uploaded, unless you share a vehicle or a save on a share host.
  • The requests below are what a mod manager needs: the list of mods, the files you install or preview, and an update check.
  • Every request carries Borea's name and version as its user agent, for example Borea/0.4.0 (+https://github.com/KSAModding/Borea), and nothing else that identifies you, except the token of a sign-in you made, which goes only to the service it belongs to. Each service sees your IP address, as with any download.

What Borea contacts by itself

These run without you asking. Each item names its switch, or says that it has none.

  • The content index, served from GitHub Pages (privacy). The list of mods, packs, vehicles, saves, share hosts and game builds, with their releases, fetched at start, when you refresh Discover, and again when a page needs it and the last check is older than ten minutes. This is what Borea is for, so it has no switch. Without it the app shows what it downloaded last.
  • Announcements, from GitHub (privacy). Short posts from the KSAModding team on Home. Off with Settings, General, "Show news from the KSAModding team".
  • The Borea releases, from GitHub (privacy). The update check at start, and the download when you update. Off with Settings, General, "Check for updates at start". Installing an update is always something you confirm.
  • The KSA master server of RocketWerkz. The current public build of the game, so Borea can tell you that your install is behind. Asked at start over plain HTTP, and only when a KSA install was found. Off with Settings, General, "Check for updates at start".
  • Listing images, from the hosts the mod authors chose. The icons and screenshots on a listing. On by default, and each request tells that host your IP address, which the setting says too. Off with Settings, General, "Load images from author hosts".
  • The 3D preview of a vehicle, from the host its release names, which can be a share host, or a mirror the index names. When you open the page of a vehicle whose file is not on your computer, Borea downloads that file after a moment, without a click, if its stated size is at most 5 MB and a game folder is set. That host sees your IP address and can count the download. A larger file, a file of no stated size, and the mods the vehicle needs wait for a click. If you press Cancel, or the download fails, that release waits for a click until Borea starts again. No switch.
  • The listing rules, from GitHub (privacy). The first time you open an instance after Borea starts, it fetches the rules of the content index, so it can tell whether Share applies to vehicles and saves. No switch.
  • A mod from SpaceDock (privacy). Only when an instance holds a mod installed from SpaceDock, for example with the CLI. Opening that instance and the update check in the App ask SpaceDock for that mod. No switch.
  • A kept GitHub sign-in. Only after you signed in with "Stay signed in on this computer" on. At each start Borea renews the token at GitHub and asks GitHub whether the account is a steward. Off with Settings, General, "Stay signed in on this computer".

What Borea contacts because you asked

  • Downloads. Installing a mod, a loader, a vehicle or a save downloads it from the host its release names, usually GitHub or SpaceDock (privacy), and for a vehicle or a save also a share host, or from a mirror the index names. Checking a manual install and importing a shared profile download the matching release too. That host sees your IP address and the download.
  • The SpaceDock mod list. Installing a pack, changing the game folder while a loader is installed, the CLI commands that search, show a mod, or list, install, adopt or set a loader, and a CLI launch when Borea holds no listing for the loader ask SpaceDock for its list of KSA mods. The search also sends your search words to SpaceDock.
  • Patch notes of newer KSA builds, from GitHub (privacy). Opening the patch notes fetches those of the builds newer than your install, unless Borea has them already.
  • Signing in to GitHub. Only if you choose to, for publishing a listing or for the steward tools. Borea uses GitHub's device flow, so your password never reaches Borea, and the token it receives goes into your system's secret store. "Stay signed in on this computer" in Settings, General decides whether it survives a restart, and you can revoke it at any time in your GitHub settings. The steward tools work on the index repositories through GitHub, read a SpaceDock mod to check who owns a listing, and can download a release archive from its host.
  • The listing tool. Publishing a listing opens a pull request on the content index with the data you entered, which is public. It also reads the prefix of the forum thread that you give or that the source names, from forums.ahwoo.com, to suggest a tag. To fill the form it reads the current listing and its rules from GitHub, reads the GitHub repository or the SpaceDock mod you name, and downloads its latest release archive. It also fetches the images of the listing from their hosts, including those of an existing listing when it opens, even when "Load images from author hosts" is off.
  • Sharing a vehicle or a save on a share host. Only if you choose to. A share host is a site with its own operator and policy that the content index names, not a server of Borea, and it sees your IP address. You sign in with a code that you enter on the host, so your password never reaches Borea, and the token goes only to that host. With "Stay signed in on this computer" on, your system's secret store keeps the token for your next share. Turning it off stops new tokens from being kept, but Borea does not remove one that is already there, so remove it in your system's secret store or at the host. The upload sends the whole folder of the vehicle or the save as an archive, with its list of dependencies, so the host has the archive before you publish. Cancelling sends nothing to the host, so an uploaded archive stays there until the host discards it. Publishing sends the version and the release status, and for a new listing its id, name, authors, abstract, license, description and tags. That data and the archive become public, and for a new listing the host opens a pull request on the content index. Pictures that you add to a share go to the host right after the publish, without the names of their files, and they become public too. For a new vehicle listing, the Publish step shows a picture that Borea drew from the vehicle on your computer, and that picture goes the same way unless you replace it or leave it out.
  • Links. Opening a link from inside Borea hands it to your browser.

What stays on your computer

Borea keeps its settings, its instances, the mods it installed, its task history, its logs, its caches and its backups in its own folders, next to the game's own data. Nothing in them is sent anywhere, except a vehicle or a save that you share on a share host. Removing those folders removes everything Borea knows, except a kept sign-in, which is in your system's secret store.

The CLI reads the same settings as the App and asks the same services, but only when a command needs them. Its command game version asks the KSA master server. It has no checks at start, no announcements, no images, no 3D preview, no sign-in, no listing tool and no upload to a share host.
